## Request Lifecycle

```text title="Alur request backend"
HTTP /api/*
 -> cookie-parser dan konfigurasi CORS
 -> Controller + guard/throttler sesuai dekorator
 -> ValidationPipe (transform=true, whitelist=true)
 -> Service domain -> Repository/Prisma -> PostgreSQL
 -> TransformInterceptor -> envelope JSON
Exception -> AllExceptionsFilter -> status HTTP dan envelope error
```

main.ts menggunakan global prefix /api. CORS memakai credentials true, metode GET/POST/PUT/DELETE/PATCH, serta Content-Type/Authorization. Origin berasal dari CORS_ORIGIN, localhost, dan domain frontend yang ditentukan source; nilai env Render belum diinspeksi.

ValidationPipe melakukan transform dan whitelist. forbidNonWhitelisted tidak diaktifkan, sehingga jangan menyatakan semua field tak dikenal ditolak. Validasi rinci berasal dari DTO; OpenAPI tidak memuat semua aturan runtime.

## Domain dan Data

AppModule mengimpor modul per domain. OrderController menerima DTO dan identitas JWT, lalu memanggil OrderService. Detail order menggunakan subject pengguna. ProductsController meneruskan filter/pagination/slug ke ProductsService. Pemisahan Repository tidak seragam, sehingga tidak semua modul diasumsikan mempunyai lapisan itu.

PrismaService memakai PrismaPg dengan DATABASE_URL, connect saat module init dan disconnect saat module destroy. [Database](/docs/developer/backend/database) menjelaskan relasi tanpa mengakses data produksi.

## Authentication dan Authorization

JwtStrategy membaca bearer dari Authorization dan memverifikasi JWT_ACCESS_SECRET. Hasil validate memuat sub/name/email/role. AuthService menerbitkan access token 15 menit serta refresh token tujuh hari. Refresh memverifikasi secret, hash tersimpan, dan expiry sebelum rotasi. RolesGuard membaca metadata role pada route yang memakainya.

Anotasi bearer pada class AuthController juga muncul di Swagger login/register/forgot/reset/verify, tetapi method tersebut tidak memasang JwtAuthGuard. Refresh memakai RefreshGuard. Cart memakai optional JWT pada beberapa operasi. PaymentController memasang JWT pada create; notification tidak memasangnya pada method. Ini bukan kesimpulan bahwa webhook bebas seluruh validasi: detail keamanan payment service perlu diaudit tersendiri dan webhook tidak dipanggil dalam pekerjaan docs.

## Response dan Error

TransformInterceptor mengembalikan success/statusCode/message (array)/data/timestamp, dengan pemisahan ServiceResult dan payload biasa. AllExceptionsFilter mempertahankan status HttpException, menormalisasi pesan menjadi array, dan mengisi data null. Exception lain menjadi HTTP 500 dengan pesan generik jika NODE_ENV production; log memakai Pino.

Source hanya mendaftarkan Swagger ketika NODE_ENV bukan production. Ketersediaan Swagger saat audit tidak digunakan untuk menebak nilai env Render.
